## Chapters 3 & 4
### Guide to Computer Processor Architecture: A RISC-V Approach (2022)

---

# Objective

The objective of this demonstration is to show the complete software development flow for the RISC-V architecture.

The demo covers:

- Cross-compiling a C program for RISC-V
- Generating RISC-V assembly code
- Generating machine-code disassembly
- Executing the program on the Spike ISA Simulator
- Understanding how high-level C code is translated into RISC-V instructions
- Observing compiler optimizations and generated assembly

---

# Chapter 3
## Cross Compilation and Spike Execution

---

## Step 1 : Open the Chapter 3 directory

```bash
cd ~/goossens-book-ip-projects/2022.1/chapter_3
```

### Explanation

This directory contains the source files used in Chapter 3.

The compiler will generate all output files inside this directory.

---

## Step 2 : View the C program

```bash
cat hello.c
```

### Explanation

This is a simple C program.

```c
printf("hello world");
```

The purpose of this program is not complexity.

Instead, it demonstrates the complete compilation process from C source code to executable RISC-V machine code.

---

## Step 3 : Compile the program

```bash
riscv32-unknown-elf-gcc -o hello hello.c
```

### Explanation

This command invokes the RISC-V cross compiler.

Unlike GCC for x86 processors, this compiler generates instructions for the RISC-V ISA.

Output:

```
hello
```

This executable cannot run directly on an Intel or AMD processor because it contains RISC-V instructions.

---

## Step 4 : Verify the executable

```bash
file hello
```

Expected output

```
ELF 32-bit LSB executable
UCB RISC-V
```

### Explanation

This confirms that:

- executable format is ELF
- architecture is RISC-V
- executable is 32-bit

---

## Step 5 : Generate Assembly

```bash
riscv32-unknown-elf-gcc -S hello.c
```

### Explanation

Instead of producing machine code immediately,

the compiler first converts C into RISC-V Assembly.

Output:

```
hello.s
```

Assembly language is human-readable.

It contains symbolic instructions such as

```
addi
sw
lw
jal
ret
```

---

## Step 6 : View Assembly

```bash
less hello.s
```

### Explain the following

### Function Prologue

Explain that the stack pointer is adjusted.

Registers are saved.

A new stack frame is created.

---

### Function Body

Point out

```
call puts
```

or

```
call printf
```

depending on the compiler.

Explain that this instruction transfers execution to the library function.

---

### Function Epilogue

Show

```
ret
```

Explain that the return instruction transfers execution back to the caller.

---

## Step 7 : Generate Disassembly

```bash
riscv32-unknown-elf-objdump -D hello > hello.dump
```

### Explanation

Unlike the assembly generated by GCC,

this disassembly is generated from the executable itself.

Therefore,

this shows the exact machine instructions that will execute.

---

## Step 8 : View Disassembly

```bash
less hello.dump
```

### Explain

Show that every instruction contains

```
Address

Machine Code

Assembly Instruction
```

Example

```
10074:
00000517
auipc
```

Explain that

- left side = memory address

- middle = machine code

- right side = decoded assembly instruction

---

## Step 9 : Execute on Spike

```bash
spike --isa=RV32IZicsr_Zifencei \
~/riscv-pk/build/pk \
hello
```

Output

```
hello world
```

### Explanation

Spike is an ISA simulator.

It fetches

↓

decodes

↓

executes

each RISC-V instruction.

The Proxy Kernel (pk) provides the minimal runtime environment required by the program.

Finally,

the program prints

```
hello world
```

which confirms successful execution.

# Chapter 4

## Understanding Generated Assembly

Chapter 4 focuses on how GCC converts C code into RISC-V instructions.

---

# Example 1

```bash
riscv32-unknown-elf-gcc -O0 -S exp.c

less exp.s
```

### Explain

Without optimization,

the compiler stores variables on the stack.

Arithmetic operations become explicit assembly instructions.

Observe

```
lw

sw

addi

mul
```

This demonstrates how arithmetic expressions are translated into RISC-V instructions.

---

# Example 2

```bash
riscv32-unknown-elf-gcc -O0 -S test.c

less test.s
```

### Explain

This example demonstrates conditional statements.

Observe branch instructions such as

```
beq

bne

bge

blt
```

Explain that the CPU changes the Program Counter depending on whether the comparison succeeds.

---

# Example 3

```bash
riscv32-unknown-elf-gcc -O1 -S loop.c

less loop.s
```

### Explain

Optimization level

```
-O1
```

reduces unnecessary instructions.

Variables remain inside registers instead of memory.

The compiler removes redundant loads and stores.

Execution becomes faster.

---

# Example 4

```bash
riscv32-unknown-elf-gcc -O1 -S fib.c

less fib.s
```

### Explain

This example demonstrates recursion.

Observe

```
jal
```

which performs the function call.

The return address is stored inside

```
ra
```

Finally,

```
ret
```

returns execution to the calling function.

# Frequently Asked Questions

## Why use a cross compiler?

Because the host computer is x86 while the target architecture is RISC-V.

---

## What is Spike?

Spike is the official RISC-V ISA simulator.

It executes RISC-V instructions without requiring physical hardware.

---

## What is the Proxy Kernel?

The Proxy Kernel provides a minimal execution environment for user programs running on Spike.

---

## What is the difference between hello.s and hello.dump?

hello.s

Generated directly by GCC.

Contains symbolic assembly.

hello.dump

Generated from the executable.

Shows the exact machine instructions stored in memory.

---

## Why does the command contain

```
RV32IZicsr_Zifencei
```

Modern versions of Spike require the ISA extensions used by the executable to be specified.

These extensions include

- Zicsr
- Zifencei

---

# Important Note

Spike demonstrates software execution.

It is **not** an RTL simulator.

Therefore,

Spike cannot generate hardware waveforms (.vcd).

Waveforms require a Verilog simulator such as

- Icarus Verilog
- Verilator
- Vivado Simulator
