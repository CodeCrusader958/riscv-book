# Chapter 5 : Fetching IP using Vitis HLS

# Top-Level Design (`fetching_ip.cpp`)

The function `fetching_ip()` is the entry point of the hardware design. During synthesis, Vitis HLS converts this function into the top RTL module.

### Function Inputs

| Argument | Purpose |
|----------|---------|
| `start_pc` | Initial Program Counter |
| `code_ram[]` | Instruction memory |

The processor repeatedly performs three operations:

```text
Fetch Instruction
      │
      ▼
Execute
      │
      ▼
Update Running Condition
```

Execution continues until a **RET** instruction is encountered.

### HLS Pragmas

```cpp
#pragma HLS INTERFACE s_axilite port=start_pc
#pragma HLS INTERFACE s_axilite port=code_ram
#pragma HLS INTERFACE s_axilite port=return
```

These pragmas generate an **AXI4-Lite Slave Interface**, allowing software to configure the generated hardware IP through memory-mapped registers.

```cpp
#pragma HLS PIPELINE off
```

Pipeline optimization is intentionally disabled to implement a simple sequential processor. Pipelining is introduced in later chapters.

# Schedule Viewer

The Schedule Viewer illustrates how Vitis HLS schedules every operation across clock cycles after synthesis. It represents the execution timeline generated by the scheduler and highlights the dependencies between operations.

### Schedule Flow

```text
Read start_pc
      │
      ▼
Initialize PC
      │
      ▼
Fetch Instruction
      │
      ▼
Execute
      │
      ▼
Update PC
      │
      ▼
Check RET
      │
      ▼
Repeat Loop
```

### Important Observations

- The design executes sequentially because `#pragma HLS PIPELINE off` disables pipelining.
- The blue bar (`VITIS_LOOP_20_1`) represents the loop controller generated by HLS.
- Green bars correspond to synthesized function executions.
- Gray blocks represent register reads, writes, and control operations.
- Purple dependency arrows indicate **data dependencies**, ensuring an operation begins only after the required data from the previous operation is available.

The Schedule Viewer confirms that the Fetch, Execute, and Running Condition stages execute in the intended order without overlap.

- Enables integration into Vivado IP Integrator

The exported IP can subsequently be instantiated in Vivado-based FPGA designs.
